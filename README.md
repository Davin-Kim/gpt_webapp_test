# MY MONEY

한국어·원화 기반 개인 가계부. 여러 해의 거래를 계속 누적하며, 아이보리·세이지 색상의 반응형 화면을 제공합니다. 실제 거래는 소스나 정적 파일에 포함하지 않습니다.

## 실행

Node.js 22 이상 권장 (검증 환경: Node.js 24).

```sh
cd /workspace/gpt_webapp_test
npm ci
npm run dev
```

개발 서버 기본 포트는 5173입니다. 배포용 파일은 `npm run build`로 `dist/`에 생성합니다. `npm run preview`로 빌드 결과를 실행할 수 있습니다. 운영 시 HTTPS 정적 호스팅을 사용하세요. localhost 개발 환경도 브라우저 파일 해시·저장 기능을 지원합니다.

## 처음 사용

**설정 → 원본 XLSX 가져오기**에서 「2026_가계부.xlsx」를 직접 선택하세요. 서버로 파일을 전송하지 않습니다. 거래 건수·기간·월별 수입/지출/수지·시작 잔액·오류 행을 검토한 후 추가 또는 전체 교체를 선택합니다. 전체 교체는 확인 후 거래와 자산을 교체하며 사용자 분류·결제수단은 보존합니다.

원본의 시작 잔액은 85,382원으로 인식됩니다. 원본에 시작 잔액 기준일이 없으므로 최초 거래일을 제안하며 사용자가 변경할 수 있습니다. 시작 잔액은 한 번 적용하고 새해에 초기화하지 않습니다. 기준일보다 이전의 거래를 등록하려면 설정에서 기준일을 먼저 조정하세요. 같은 브라우저에 이미 기록이 있으면 앱이 자동으로 덮어쓰지 않습니다.

## 기능과 계산

- 대시보드: 월/연간 보기, 여러 해의 월 이동, 수입·전체 지출·수지, 별도의 누적 장부 잔액·총자산, 수입/지출 분류별 금액·비중, 최근 6개월/연간 월별 수입·지출 차트 및 수지 표, 소액·신용카드·경조사/용돈 지출, 주차별 지출·건수·평균, 최근 거래.
- 거래: 추가·수정·삭제 확인, 저장 후 계속 입력, 입력란별 오류 안내, 한국 날짜 기본값, 금액 쉼표, 월·기간·구분·분류·결제수단 필터, 내용/메모 검색, 날짜·금액 정렬, 30건씩 페이지 탐색.
- 자산: 예금/적금/투자/현금/기타 추가·수정·삭제 및 구분별 합계. 빈 금액은 미입력으로 보존하고 합계에서 제외. 현재 금액은 직접 수정합니다.
- 설정: 분류 및 결제수단 추가·이름 변경·비활성화. ID 참조를 유지하므로 과거 기록이 사라지지 않습니다. 이름 변경은 과거 표시에도 반영됩니다. 지출 분류를 소비 또는 저축/투자로 지정할 수 있습니다.
- JSON 전체 백업/검증 후 복원, XLSX 거래·자산 내보내기와 재가져오기. 파일 SHA-256 중복 방지로 동일 파일 추가는 차단하고, 같은 날짜·금액·내용의 정상 복수 행은 모두 보존합니다. 수정·재저장한 파일은 다른 파일로 취급하므로 겹치는 거래가 있는 수정본은 백업 후 전체 교체하세요.

월 수지는 선택 기간의 수입−전체 지출입니다. 전체 지출에는 저축/투자가 포함되고 소비 지출에서는 제외합니다. 수입 대비 잔여율은 `(수입−전체 지출)/수입`; 수입이 0이면 계산 불가입니다. 거래별 잔액은 **날짜 오름차순, 같은 날짜는 원본 행/등록 순서**로 재계산합니다. 목록의 정렬·필터는 이 계산에 영향을 주지 않습니다. 누적 잔액은 선택 기간과 관계없이 최초 시작 잔액+모든 수입−모든 지출입니다. 신용카드 지출도 거래 시점에 차감하므로 실제 은행 잔액과 다릅니다. 자산과 장부를 합산하지 않습니다.

주차는 1~7일, 8~14일, 15~21일, 22~28일, 29일~말일입니다. 연간 주차 표는 각 월의 동일 구간을 합산합니다. 날짜는 `YYYY-MM-DD` 달력 문자열이며 오늘만 Asia/Seoul로 결정합니다.

## 원본 분석 및 검증 결과

HOME·입력·자산 시트, 병합 셀, 수식과 드롭다운을 직접 확인했습니다. HOME F7/H7/J7 및 여러 비중 수식은 빈 병합 셀 C7/E7을 참조합니다. 앱은 이를 복사하지 않고 거래 합계로 계산합니다. 원본 5주차 수식의 경계도 앱에서는 요청한 29일~말일 기준으로 계산합니다. 입력은 헤더를 찾고 실제 수입/지출 행만 읽습니다. 설명 병합 행, 빈 행, 잔액 수식만 있는 행은 제외합니다. 거래 분류를 내용에 맞춰 임의로 수정하지 않습니다. 원본 파일은 읽기만 수행했고 전후 SHA-256이 동일했습니다.

| 검증 | 건수 | 수입 | 지출 | 수지 |
|---|---:|---:|---:|---:|
| 2026년 9월 | 31 | 1,788,611 | 923,293 | 865,318 |
| 2026년 10월 | 8 | 0 | 500,440 | -500,440 |

39건의 날짜·구분·분류·내용·결제수단·금액·메모를 원본 행과 일대일 비교했습니다. 시작 잔액 **85,382원**, 최종 누적 장부 잔액 **450,260원** 일치. 원본 자산 6개를 모두 미입력으로 보존했습니다.

계산·저장·가져오기 Node 테스트 8개 및 실제 Chromium 브라우저 시나리오 7개를 실행했습니다. 거래/자산 CRUD, 과거 거래 변경 후 잔액, 2026년 12월→2027년 1월 및 연간 집계, 빈 월·수입 0, 새로고침 및 브라우저 프로세스 재실행, JSON 복원, XLSX 왕복, 중복 가져오기, 분류/결제수단 관리와 검색·필터, 저장 실패 후 재시도, 390px 모바일 화면을 검증했습니다. 연말·연초 테스트 거래는 격리된 테스트 브라우저/메모리에만 사용하며 초기 데이터나 실제 기록에 남기지 않습니다. 프로덕션 빌드 성공, npm audit 알려진 취약점 0건 확인.

```sh
npm test
npm run test:e2e
npm run build
```

실제 원본 검증을 다시 실행하려면 비공개 파일 경로를 지정하세요. 원본 경로가 없으면 원본 전용 테스트 2개는 명시적으로 건너뛰며 일반 테스트는 실행됩니다.

```sh
ORIGINAL_XLSX=/private/path/2026_가계부.xlsx npm test
ORIGINAL_XLSX=/private/path/2026_가계부.xlsx npm run test:e2e
```

브라우저 테스트 기본 실행 파일은 `/usr/bin/chromium`이며 `CHROMIUM_PATH`로 변경할 수 있습니다. 시스템 Chromium이 없으면 Playwright의 Chromium을 설치하고 설정의 실행 파일 경로를 해당 브라우저로 지정하세요.

## 저장 방식과 구조

`src/model.js`: 계산·날짜·유효성 / `src/storage.js`: IndexedDB 저장 어댑터 / `src/excel.js`: 파일 파싱·내보내기 / `src/app.js`: 화면·상호작용 / `src/style.css`: 반응형 스타일. 저장 어댑터를 교체해 향후 서버 저장으로 확장할 수 있습니다. ExcelJS는 파일 기능을 사용할 때만 로드합니다. ExcelJS의 uuid 의존성은 호환 API를 제공하는 패치 버전으로 override했습니다.

DB 이름은 `my-money-private`, 오브젝트 저장소는 `state`입니다. 저장 트랜잭션이 완료된 뒤에만 화면 상태와 성공 안내를 갱신합니다. 저장 실패 시 입력을 유지하고 같은 버튼으로 재시도할 수 있습니다. 데이터는 브라우저 프로필과 접속 origin(주소·포트)에 종속됩니다. 로그인·서버 저장·기기 간 동기화는 없습니다. 브라우저 초기화·시크릿 모드·용량 부족에 대비해 JSON 백업을 보관하세요. 동시에 여러 탭에서 편집하는 사용은 권장하지 않습니다. XLSX는 거래·자산 교환용이며 분류 활성 상태 등 모든 설정의 완전한 복원은 JSON 백업을 사용하세요.

XLSX는 15MB 이하이며 헤더 기반 표 형식을 지원합니다. 이번 원본 배치는 실제 검증했습니다. 다른 비표형 자산 배치를 인식하지 못하면 경고하며 추측해서 가져오지 않습니다. 테스트 결과·브라우저 캡처와 원본 파일은 Git/정적 빌드에 포함하지 않습니다. 개발 서버에서도 XLSX 직접 제공과 checkout 밖 파일 접근을 차단합니다. 기기의 악성코드나 브라우저 프로필 접근에 대한 별도 암호화는 제공하지 않습니다.

## GitHub Pages 배포

이 저장소의 Pages 접속 주소는 **https://davin-kim.github.io/gpt_webapp_test/** 입니다. Vite `base`는 `/gpt_webapp_test/`로 설정되어 있으며 개발·미리보기에서도 이 경로로 접근합니다.

GitHub에서 다음 설정을 한 번 수행하세요.

1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
2. **Settings → Actions → General**에서 GitHub Actions와 워크플로에 사용된 GitHub 공식 액션을 허용합니다. 조직 정책이 있으면 관리자의 허용이 필요할 수 있습니다.
3. 앱 파일, package-lock.json, Vite 설정과 `.github/workflows/deploy-pages.yml`을 기본 브랜치 **main**에 커밋·푸시하거나 PR로 병합합니다.
4. **Actions → Deploy MY MONEY to GitHub Pages**에서 실행 결과를 확인합니다. 필요하면 **Run workflow**로 수동 실행할 수 있습니다. `github-pages` 환경에 승인 규칙이 있다면 배포를 승인하세요.

이후 main에 변경이 반영될 때마다 Node.js 24에서 `npm ci` → `npm test` → `npm run build`를 실행하고, 성공한 **dist 폴더만** Pages에 업로드·배포합니다. 기본 GITHUB_TOKEN과 Pages OIDC 인증을 사용하므로 별도의 토큰이나 비밀값을 추가할 필요가 없습니다. 기본 브랜치를 main에서 바꾸면 워크플로의 push.branches도 변경해야 합니다. 원본 파일이 없는 CI에서는 원본 전용 Node 테스트 1개가 명시적으로 건너뛰어지며 일반 계산·저장 테스트 7개는 실행합니다.

개인 엑셀과 백업은 커밋하지 마세요. XLSX 등 스프레드시트, 앱 이름의 JSON 백업, attachments/backups 경로는 .gitignore에서 제외합니다. publicDir는 비활성화되어 있고 빌드에는 앱 코드만 포함됩니다. 워크플로도 dist의 스프레드시트·JSON·CSV 파일을 발견하면 배포를 중단합니다. 기존 거래는 배포된 앱의 **설정 → 원본 XLSX 가져오기**에서 직접 등록합니다.

배포 주소는 로컬 개발 주소와 origin이 다르므로 기존 로컬 IndexedDB가 자동 이동하지 않습니다. JSON 백업 복원 또는 엑셀 가져오기를 사용하세요. 같은 GitHub Pages origin에 있는 다른 가계부 복사본은 동일 DB 이름을 공유할 수 있습니다. 실제 GitHub 배포는 main 반영 및 Pages 설정 후 GitHub에서 실행되며 로컬 빌드 성공과 별개의 단계입니다.
